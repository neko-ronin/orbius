Scope: exact npm release artifacts react 19.2.8, react-dom 19.2.8, vite 8.2.2;
resolved application lockfile; temporary formatting tool prettier 3.9.6;
and the newly authored application. This is an artifact-level bounded review,
not a complete upstream Git-history audit. All applicable sections of the
parent VET_REPO.md procedure were considered. Unavailable evidence is stated.

2. SECURITY
   No malicious instruction text found in the scanned package README/JS/MD
   content for the specific injection markers searched (including "ignore
   previous instructions" and APPEND_SYSTEM). This is not proof that every
   possible prompt injection is absent. External content was treated as data.
   No project-local .pi/.prime/.claude/.cursor agent configuration, SYSTEM.md,
   APPEND_SYSTEM.md, or AGENTS.md was found in the reviewed release artifacts.
   BOAST does not load executable agent extensions or scripts from project files.

   AMBER | Vite can execute trusted project JavaScript/configuration at build
   or development time. Its evalValue helper evaluates static worker/glob
   options with new Function; the call sites in worker parsing were inspected.
   SSR stacktrace code uses new Function for offset calculation. These are
   tooling mechanisms, not a safe execution boundary for an untrusted repo.
   Use Vite only on source you trust. This new workspace has no imported
   remote source or third-party Vite plugins.

   Vite base64 matches were source-map/data-URL decoding and a bundled WASM
   parser. Prettier uses new Function for dynamic import compatibility. Its
   apparent AWS-key-shaped matches were repeated byte sequences inside the
   Flow parser's embedded WebAssembly payload, not credential declarations.
   No live secret-shaped strings were found in reviewed React/Vite artifacts.
   The new workspace has no previous Git commits or remote; Git-history
   secret sampling and top-author/commit-count analysis are unavailable.
   Upstream histories were not cloned or sampled.

   Network surface: React package links point to documentation, GitHub and
   W3C namespaces. Vite's WebSocket server supports local HMR; its fetched
   WASM URLs are derived from application imports. Inspected personal-domain
   references were license attributions or parser-reference comments, not
   exfiltration targets. Prettier scan found no fetch/http.request call sites.
   Full dynamic execution tracing of all transitive/native code was not done.

   Telemetry: no telemetry/event-sending mechanism identified in the reviewed
   direct release artifacts. Therefore no telemetry endpoint, event fields,
   default collection state, or opt-out applies to the authored app.
   BOAST's runtime makes no external requests. Fonts, icons and graphics are
   local/procedural. Learning links navigate to Google only when clicked.
   Local autosave stays in browser storage; JSON/GLSL/image/video exports stay
   in downloads. Vite's development HMR connection is local.

   Project imports are JSON, not evaluated JavaScript. They are bounded to
   250 KB, 20,000 characters per shader, 24 nodes and 12 fields, with finite
   numeric range validation, unique IDs and cycle checks. GLSL is submitted
   to the browser GPU compiler; pathological authored shaders can still
   stall the GPU or lose the context. Compilation failures retain the last
   working program. This is not a shader resource-isolation sandbox.

   Advisory/news review:
   - React Server Components had RCE and later denial-of-service advisories.
     BOAST uses client React/React DOM 19.2.8 and has no RSC dependency/server.
     Official source: https://react.dev/blog/2025/12/03/critical-security-vulnerability-in-react-server-components
   - Vite has published development-server file-access advisories. The current
     official pinned 8.2.2 tree reports no known vulnerabilities in npm audit.
     The preview binds 127.0.0.1 and is not exposed to the network.
     Official source: https://github.com/vitejs/vite/security/advisories?state=published
   - A verified 2025 malware incident affected eslint-config-prettier,
     eslint-plugin-prettier and related packages, not this direct formatter
     package. None of those integration packages is installed for BOAST.
     Source: https://github.com/advisories/GHSA-f29h-pxvx-f335
   - Searches surfaced secondary claims about Vite-namespace impersonation;
     this review did not establish primary evidence tying those claims to
     the official pinned vite release. No similarly named plugin was used.
   No corroborated compromise of the selected exact releases was found in
   this bounded search. A clean search/audit is not a malware guarantee.

   Only runtime dependencies: react 19.2.8 and react-dom 19.2.8; Vite 8.2.2

4. INSTALLER
   Direct release archives were downloaded by npm pack --ignore-scripts to
   temporary storage, extracted and inspected without running their code.
   Dependency resolution used --package-lock-only during the initial audit.
   Installation followed that review via npm ci --ignore-scripts.
   npm verifies package integrity against the lockfile's SHA-512 values.
   Those hashes are registry-supplied, not an independent publisher audit.
   Native Rolldown/Lightning CSS platform artifacts came from npm packages.
   No remote script was piped to an interpreter, no sudo was used, and no
   global application package installation was made.

5. CODE QUALITY
   Clean separation: project schema/metadata, WebGL ownership, GLSL programs,
   node interaction, and React studio UI. No general-purpose framework was
   created around the renderer. No JavaScript eval in BOAST source.
   Eight meaningful unit checks cover file round trips, range/schema errors,
   graph topology, disconnected effects, shader drafts and duplicate IDs.
   Production build succeeds. Real-browser checks cover the key UI paths;
   real exported media was decoded/inspected separately.
   Limitations: no full upstream source or binary audit; no cross-GPU/browser
   compatibility matrix; custom GLSL has no hard execution timeout; no undo
   stack or bit-exact GPU simulation checkpoint.
